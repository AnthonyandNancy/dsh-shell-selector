Requirements:

1. On Windows discover Bash candidates in this order:
   - PATH bash.exe, rejecting exactly %SystemRoot%\\System32\\bash.exe as the WSL launcher.
   - PATH git.exe-derived Git root: <root>\\bin\\bash.exe and <root>\\usr\\bin\\bash.exe.
   - %ProgramFiles%\\Git\\bin\\bash.exe and usr\\bin\\bash.exe.
   - %ProgramFiles(x86)%\\Git\\bin\\bash.exe and usr\\bin\\bash.exe.
   - %LOCALAPPDATA%\\Programs\\Git\\bin\\bash.exe and usr\\bin\\bash.exe.
   Deduplicate executable paths case-insensitively.
2. A Bash candidate is available only when it is a file/executable and passes both argv probes:
   - executable --version
   - executable -c printf '%s' "$BASH_VERSION"
   Use spawn/spawnSync argv arrays, timeout, windowsHide, and no shell-string interpolation. Probe failure means unavailable.
3. Return kind, display name (Git Bash for Git-for-Windows candidates), source (path, git-for-windows, well-known, or system), executable/path compatibility, and best-effort version. Preserve PowerShell 7 and Windows PowerShell detection.
4. Keep Windows auto fallback Bash/Git Bash -> PowerShell 7 -> Windows PowerShell. Keep POSIX default behavior.
5. Boot expressions must match the TypeScript resolver/detector and must have no preset gate. Patch must enable exactly one executor. When the active validated Bash is Git Bash outside PATH, the plugin must prepend the Git Bash bin directory to the current process PATH only; do not modify persistent environment variables.
